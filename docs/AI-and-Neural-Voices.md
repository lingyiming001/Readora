# AI 阅读助手与自然音色

## 已实现（0.6.0，含0.5.0多模型）

设置 → AI：启用开关、供应商、API地址、模型ID、API Key、获取模型列表、测试连接与保存。预设 OpenAI、DeepSeek、通义千问（北京地域）、Ollama（本机11434）及自定义 Chat Completions 兼容接口。模型ID由用户填写或从服务获取，不内置易过期的模型名单。

书库“AI 助手”、阅读器右上角星光按钮、正文选区右键“用 AI 解读所选文字…”均可打开助手。支持解释、摘要、翻译为中文和自定义问题；原文可先预览编辑，单次最多6000个字符，问题最多1200个字符。PDF默认使用当前页可提取文本，不包含OCR。没有全书索引/RAG或多轮聊天历史。

只有用户点击发送、测试连接或获取模型才会发出网络请求。连接测试仅发送固定测试句，不发送正文。AI默认关闭。云服务可能计费，实际模型可用性与额度由供应商账号决定。

API Key使用Security.framework保存到系统钥匙串，按供应商和规范化API地址分开；不放入JSON、书籍、日志或URL。切换供应商/地址不会把旧密钥带到新地址，模型切换可复用同一服务密钥。保存时留空保留已有密钥，移除需界面确认。配置文件只存启用状态、供应商、地址和模型。软件更新后如系统提示钥匙串访问，请自行核验并授权。

网络使用临时URLSession，不缓存响应/Cookie、不跟随重定向；HTTPS用于远程服务，仅字面回环地址允许HTTP。请求/总资源超时60/120秒，回复最多接收1MiB，回答输出预算1800 token。取消会中止任务并忽略过期结果。回答纯文本显示，可复制。普通问答不执行操作；“操作应用”模式仅执行白名单工具，删除类操作还需用户确认。

| DeepSeek | https://api.deepseek.com/v1 | 供应商API Key |
| 通义北京 | https://dashscope.aliyuncs.com/compatible-mode/v1 | 同地域API Key |

## 开源自然音色候选

这些是语音生成模型，不能作为macOS系统音色直接下载安装到当前选择器。本轮加入资料入口，尚未集成推理引擎或下载权重；当前实际朗读仍使用系统语音。

| 方案 | 已核实特点 | 项目建议 |
| --- | --- | --- |
| [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) | 0.6B/1.7B、多语言、预设音色与风格控制，Apache-2.0 | 中文真人感的优先试听候选；先比较自有样章与本机延迟 |
| [CosyVoice](https://github.com/FunAudioLLM/CosyVoice) | 多语言、流式语音生成；官方项目提供模型/部署代码 | 适合评估长文流式朗读；部署依赖较多，按具体版本核查环境 |
| [Kokoro-82M-v1.1-zh](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh) | 82M、中文/英文音色、Apache-2.0 | 较轻量的本机候选；中文v1.1并非所有旧音色的严格升级 |

音质“更像真人”的排序没有在本机做盲听验证；官方样例是候选依据，不能代替实际延迟、长文稳定性、发音与能耗评测。建议用多音字、人物对话、中英混排与长句样章试听，再决定本机独立服务或远程推理方案。不要把LLM API Key等同于这些开源TTS模型的推理服务密钥。

## 验证边界

0.6.0 共63项无界面测试通过，含AI URL/凭据隔离、配置持久化、请求正文边界、模拟回答和模型列表、401、异常响应、过大响应及原有阅读回归。测试使用虚构密钥与自制材料，没有调用真实供应商。系统钥匙串真实密钥写入/读取和供应商付费调用需在用户配置后验证；不把模拟服务成功描述为真实模型验证。

## 多模型与应用工具

设置页维护有序模型列表，支持新增、编辑、启用、停用、排序和删除；每项可从供应商获取模型列表。默认采用顺序中首个已启用模型，不在失败后悄悄切换供应商；手动路由仅用于当前助手选择。一次请求固定使用开始时选定的配置。配置保存在 ai-models.json，旧 ai-configuration.json 只迁移一次；同供应商和规范地址的模型共用对应钥匙串凭据。

没有选文时也能直接提问、解释单词或翻译。选择“操作应用”并提交任务后，模型可以查询书籍/书架/标记/音色/模型列表，创建或重命名书架，修改书架归属、收藏与读完状态，调整阅读主题、字体、布局、朗读与导入上限，操作导航和朗读，新增书签或高亮，以及管理模型。导入会打开系统文件选择器，文件仍由用户选择；不同服务的新密钥在设置中手动输入。

移入回收站、永久删除书籍、清空回收站、删除书架/模型、移除标记和清除朗读历史都先显示具体对象与影响。用户拒绝即终止当前任务，模型无法通过传入“已确认”绕过门槛。清空操作绑定确认前的书籍快照，之后进入回收站的书不会被顺带删除。永久删除保留导入源文件，清理应用内副本、封面、缓存与标记；事务日志支持下次加载时恢复未完成操作。

工具数据可能包含书名、作者、状态、书架、标记短摘录和操作结果，并发送给所选服务；正文仍由预览明确提供。工具不提供 API Key、任意文件路径、系统命令或操作系统控制。每次任务最多6轮模型响应、12次工具调用，保留实际执行结果；无工具调用时明确显示未执行操作。

应用操作需要模型支持 function tools，参见 [官方工具调用协议](https://developers.openai.com/api/docs/guides/function-calling)。当前验证使用模拟 HTTP 与隔离书库，覆盖路由、迁移、拒绝确认停止、删除快照、事务恢复及切书期间的状态保护；没有调用真实模型，也未进行界面测试。
