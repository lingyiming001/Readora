# 19 · macOS / iOS 发布方案

## 渠道与配置

iOS 使用 TestFlight → App Store；macOS 首发 Mac App Store，外部分发与 notarization 仅作为后续渠道评估，不默认双渠道维护。Bundle ID、CloudKit 容器、App Group 和签名 Team 在工程阶段确定，Debug/Release 环境分离，禁止测试污染用户生产库。

最低 deployment target 为 iOS 17/macOS 14；上传所需 Xcode/SDK、App Store Connect 规则会变化，提交前从 [Apple upcoming requirements](https://developer.apple.com/news/upcoming-requirements/) 和 [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) 重新核验并记录日期，本文不固定未来 SDK 截止要求。2026-10-15 核验时，Apple 页面已要求自 2026-04-28 起 iOS 上传使用 Xcode 26 或更新版本及 iOS 26 SDK；这不改变本产品 iOS 17 的运行最低版本。

## Beta 验收

邀请20–30位读者覆盖iPhone低内存/旧系统与Mac最低系统；每人执行导入三格式、长时间阅读、听书、后台、重开恢复。两设备账户测试包含离线同时编辑、缺原文、配额不足。样书由用户授权，报告默认不上传原文；收集失败步骤、系统版本、脱敏事件ID。

为审核提供自制无版权障碍样书与复现步骤，不要求审核员登录第三方服务。解释后台音频用于用户主动启动的朗读；云端功能可选且离线仍可阅读。基础版商业化假设先验证买断，若后续销售数字服务/AI额度须重新核验适用购买规则。

## 上线与故障响应

正式发布先小范围分阶段放量（按渠道实际能力），每批检查启动崩溃、导入失败、位置恢复、TTS中断与同步投诉；不采集正文或默认上传细粒度阅读轨迹。达到数据丢失或破坏性迁移级别立即暂停推广、准备热修与用户恢复说明；App Store 不保证二进制即时回滚，因此新 schema 保持向前兼容且用可关闭的新功能入口降低影响。

本地只读/导出路径必须在云端故障时仍可用。关闭同步不能删除书库；修复发布前用受影响数据库副本复现（用户明确授权）。高风险数据问题目标1个工作日内确认、给出临时恢复方案；修复时间依严重程度说明，不承诺不现实的审核时限。

## 后续维护

语义版本 MAJOR.MINOR.PATCH；数据 schema 和 textVersion 独立演进。每次系统大版本前跑两平台引擎/音频回归，依赖升级固定 tag、审许可与迁移；Readium 若重新引入必须重评原生 Mac 支持，不沿用旧假设。每季度复核容量、兼容性和用户反馈，优先修可靠性，再评估 V1.1 与 AI。

本套文档最初交付为设计基线；当前已有本地签名的macOS 0.2.0原型和自动化测试，实际功能与限制以README为准。尚未创建生产iCloud容器、上传TestFlight或提交App Store，完整发布证据仍由后续阶段产生。
