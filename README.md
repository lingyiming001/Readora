# Readora

Readora 是面向 Mac、iPhone 的原生个人电子书阅读器产品设计，强调安静阅读、可靠的本地书库，以及阅读和系统朗读之间连续的上下文。未来扩展 iPadOS，保持共享领域模型与平台独立交互。

**当前状态：2026-10-16，macOS 原型 0.6.0，提供 Swift Package 原生应用、多模型 AI 助手与应用操作；尚未创建双平台 Xcode 工程，也未完成完整 MVP 或真机性能验证。** 所有指标是验收目标，不是实测结果。现有 `Readora.png` 保留原样，未被定义为已批准的品牌或 UI 规范。

## 目标架构边界（完整产品设计）

- 最低 iOS 17、macOS 14；原生 macOS AppKit 宿主，不采用 Mac Catalyst。
- Swift 6 工具链、SwiftUI 界面、必要的 AppKit/UIKit 桥接；部署基线与构建 SDK 分开管理。
- EPUB：共享安全解析器、WKWebView 渲染；PDF：PDFKit；TXT：共享文本索引、TextKit 2 平台适配。
- Core Data 本地持久化；后续通过 NSPersistentCloudKitContainer 镜像私有元数据；原始文件独立使用用户可选 iCloud Drive 文件传输。
- AVSpeechSynthesizer 为首发语音引擎；iOS 音频会话与后台播放必须先通过真机门槛。
- MVP 为本地完整闭环；同步、批注、全文搜索和高级分页分批交付，见功能规格。无 DRM 解密、云端内容上传、在线书城。

## 开发启动指南

1. 先执行路线图阶段 1 的三个技术探针：跨平台 EPUB 定位、iPhone 后台朗读、Core Data 同步冲突。每个探针交付可复现样书、测试步骤和 go/no-go 结论。
2. 创建 `Readora.xcodeproj`，两个 application target：`ReadoraMac` / `ReadoraiOS`；按工程结构创建本地 Swift Package。示例目录是未来工程蓝图，并非已有文件。
3. 使用可构建 iOS 17 / macOS 14 deployment target 的稳定 Xcode，记录确切版本到 CI；避免使用 beta SDK 才有的 API。Swift 6 并发模式逐模块启用，领域层先达到严格检查。
4. 无付费开发者账号也应先实现本地流程；CloudKit、设备签名与 TestFlight 需要配置 Team、Bundle ID 和正式容器。不得将示例标识直接用作生产配置。
5. 建好工程后运行 `xcodebuild -list -project Readora.xcodeproj` 确认 scheme；按测试文档在 CI 配置模拟器与 macOS 测试。目前运行构建命令会因工程不存在而失败。
6. 任务按「功能 ID、依赖、输入输出、失败状态、测试夹具、验收证据」编写；改变位置模型、同步协议或版本范围时先更新对应文档。

## 启动 macOS 初始版

安装 Xcode 后在项目目录运行：

```sh
./scripts/run-macos.sh
```

脚本构建 Swift Package、生成并本地签名 `deploy/Readora.app`，随后打开应用。可用 Xcode 打开 `Package.swift` 阅读和调试。当前版本默认支持200 MB以内的无加密重排EPUB 2/3、UTF-8/带BOM UTF-16 TXT和未加密PDF；支持书库搜索、EPUB书名/作者/封面、章节目录、正文图片、EPUB/TXT字号调整与系统朗读、阅读进度保存。暂不支持iOS、同步和自由文本笔记。

当前书库元数据暂用原子JSON存储，EPUB位置记录章节资源路径和段落索引，TXT/PDF保留段落/页索引；它们尚未达到文档中的Core Data、引用文本校验和跨设备定位架构。原文复制到应用支持目录，源文件不修改。本地数据位于 `~/Library/Application Support/Readora`。

测试命令：

```sh
CLANG_MODULE_CACHE_PATH=/tmp/readora-clang-cache swift test --disable-sandbox --cache-path /tmp/readora-spm-cache
```

### 应用图标

使用根目录 `Logo.png` 作为图标原稿，保留原有构图。`scripts/generate-app-icon.sh` 生成 macOS 各尺寸和 Retina 图标并打包为 `Resources/AppIcon.icns`；启动脚本自动重新生成、复制到应用包并配置 `CFBundleIconFile`。修改 Logo 后重新运行启动脚本即可。

### EPUB 支持与边界

当前采用安全解析后的原生 SwiftUI 段落排版，尚未使用目标方案中的 WKWebView。支持常见良构 XHTML 正文、spine 顺序、EPUB 3 nav/EPUB 2 NCX、标题层级、PNG/JPEG/GIF 静态图片、封面及系统朗读；书籍脚本不执行，远端资源不请求。复杂 CSS、嵌入字体、精确表格/数学排版、链接与脚注交互、固定版式、竖排、DRM/加密资源和 SVG 专属页面尚不支持。固定版式/加密包会拒绝导入；不完整 XHTML 返回可理解错误。

导入上限默认200 MB，可在「Readora → 设置…」（⌘,）或侧栏「设置」中配置为1–2048 MB（每MB按1024×1024字节计算），点击保存后生效并在重启后保留；不影响已有书籍打开。设置控制EPUB/TXT/PDF原始文件大小，内容兼容性与解析安全限制独立生效：单ZIP条目64 MB、展开总量1 GB、10,000条目、压缩比250:1；单XML8 MB、嵌套128层、正文合计8 MB。插图改为按需读取，不再将全书图片存入解析缓存；安全校验仍保留。原文以1 MB分块复制并计算SHA-256，复制中持续检查大小；解析尽量使用内存映射。资源只在内存解包，不创建书内路径。解析缓存位于书库 `Cache/`，删除后可从原文重建；缓存版本随解析规则变更递增。

自制样书位于 `Tests/ReadoraCoreTests/Fixtures/ReadingJourney.epub`，可用 `python3 scripts/generate-epub-fixture.py` 确定性重建；内容为项目自制 CC0 测试材料。测试覆盖压缩/未压缩ZIP、目录、图片、元数据、锚点、旧书库兼容、异常输入和5,000段长章。

调试构建可通过 `READORA_TEST_LIBRARY` 指定独立测试书库，Release构建忽略该变量；窗口会标记“测试”，不应将测试根目录作为长期书库。打包时可设置 `READORA_SKIP_LAUNCH=1` 只构建不打开。

### 大小上限回归

使用实际生成的200 MB EPUB验证导入和缓存删除后的重新打开；200 MB + 1字节在默认设置下拒绝，将上限改为201 MB后可导入。测试也覆盖设置持久化、非法配置不覆盖旧值、调低上限不影响已有书籍。大样本主要通过合法未使用资源填充压缩包，用于验证文件大小通路，不代表所有200 MB复杂书籍的排版或性能均已达标。

## 阅读与书库增强（2026-10-15）

- 书库：收藏、正在读/已读筛选、自定义书架、网格/列表、排序、回收站与还原。移入回收站保留文件和标记，没有永久删除入口。
- 阅读：EPUB/TXT可切换连续滚动与按实际窗口/字体计算的分页；分页支持左右箭头（阅读区域获得焦点时）、按钮、触控板横向滑动和留白处鼠标拖动，使用整页横移过渡，尊重系统减少动态效果设置。正文长段落可跨页，页内UTF-16偏移持久化。
- 外观：阅读器右上角“阅读外观”提供纸白/暖砂/浅绿/夜间主题、宋体/苹方/衬线/圆体、字号、行距、段距、页宽与页面亮度。亮度只覆盖阅读区域，不改系统屏幕设置。
- 书签与高亮：阅读器顶部书签按钮保存当前位置；文字选区右键可用金黄/薄荷/玫瑰高亮，不选择文字则标记该段/当前页片段。顶部目录弹出面板提供目录、书签、高亮及跳转/移除。PDF使用原生选择与内存高亮注释，标记另存JSON，原始PDF不被改写。
- 全局主题：设置窗口“外观”标签提供纸白、暖砂、浅绿与夜间主题，同时应用于书库、阅读器和设置窗口，自动保存。阅读器默认苹方26号、960点页宽和分页模式；已有自定义偏好保留，可用“恢复阅读默认设置”切换新版默认排版。
- 朗读：设置“朗读”提供0.5–8倍速、可配置最高速度、常用倍速按钮、本机音色与语言筛选及试听。超过2倍使用系统默认语速生成短块PCM，再经AVAudioUnitTimePitch保持音调加速；短块限制峰值内存，音频节点按格式复用。自然语速随音色变化。
- 选区朗读：选择正文后点击朗读，从选区的UTF-16起点继续到后续正文；播放中选择会跳到所选位置。右键也可“从这里开始朗读”。鼠标/键盘选区监听合并，绘制高亮不触发选区重播。
- 朗读高亮：设置或阅读器的朗读弹出面板可开关；普通速度按词、高速模式按短块高亮，永久阅读标记独立保存。播放时切换高亮不重启音频；改变速度或音色从当前朗读位置重启，暂停状态保持暂停。朗读功能针对EPUB/TXT。
- 书库视觉：统一暖白/夜间底色、中性进度条、较紧凑的继续阅读卡片与独立列表行；沉浸阅读隐藏书库侧栏和系统标题文字，标题居中、工具收为浮动控件，底部居中显示页码。

这些增强目前只针对macOS原型；完整出版者CSS、iOS、同步与Core Data仍未实现。页码随版式变化，稳定位置仍以资源/段落/偏移为准。阅读偏好、朗读偏好、书架与标记分别原子写入书库中的reading-preferences.json、speech-preferences.json、collections.json和marks.json。

验证记录：36项自动化测试全部通过，原有导入/书库/标记测试通过，并增加8倍速离线音频时长、旧版朗读JSON兼容、emoji选区/分块完整性、滑动方向与初始手指抖动测试。隔离样书GUI已核对新版沉浸排版、音色菜单、Tingting 8.00×试听启动/结束及保存。正式书库3本书正常载入，设置夜间主题已切换核验并恢复纸白。最新选区自动跳读、真实拖动与长时连续音频尚待人工回归；自动化拖动/捕获接口出现noWindowsAvailable/timeout，线程采样显示应用主线程正常等待事件。最低系统和Instruments帧率/能耗尚未实测。

音频实现依据 Apple 官方 [语音缓冲生成接口](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/write(_:tobuffercallback:)) 与 [音频播放节点](https://developer.apple.com/documentation/avfaudio/avaudioplayernode)。

### 最近朗读（0.3.1）

书库顶部固定显示最近开始朗读的3本书，搜索只筛选下方书籍，不隐藏该区域。重复朗读同一本书置顶，第四本替换最旧一本，记录单独持久化至speech-history.json。首次升级从既有最近阅读记录迁移；“清除朗读记录”确认后写入空记录，重启不再自动补回，且不修改书籍、进度与标记。下次朗读重新记入。回收站书籍隐藏，恢复后仍按保留的记录显示。

### AI 阅读助手（0.4.0）

在设置的 AI 标签配置供应商、API 地址、模型和钥匙串 API Key；书库/阅读器的 AI 助手及选区右键支持解释、摘要、翻译和提问。默认关闭，原文先预览、点击后发送，最多6000字。支持 OpenAI、DeepSeek、通义千问、Ollama 和自定义 Chat Completions 兼容接口。模型列表与连接测试需用户主动点击。配置文件不含密钥。

开源自然音色推荐与接入边界、API 地址和验证说明见 [AI 与自然音色](docs/AI-and-Neural-Voices.md)。目前推荐模型尚未内置推理引擎，朗读仍为系统语音；43项自动化测试通过，真实云服务与密钥写入仍需用户配置后验证。

### 界面修复（0.4.1）

API Key输入框改为独占行、明确边框与最小宽度，提供显示/隐藏；读取保存配置不再触发供应商切换逻辑清空模型。取消请求离开设置后不会遗留忙碌禁用状态。回收站隐藏页内/工具栏导入按钮，禁用导入菜单快捷键，空状态不再提示导入。书库/阅读/设置/AI使用统一主题背景与工具栏配色，表单与原文编辑器关闭系统滚动背景，主题切换保留表单状态。PDF原始页面内容颜色仍保留。

按用户要求，本次仅代码检查、编译与打包，不运行界面测试、不启动或关闭现有窗口。退出旧版后重新打开deploy/Readora.app验证。

### 多模型 AI 与应用操作（0.5.0）

设置 → AI 可添加多个模型、获取服务模型列表、启用/停用和调整顺序；自动路由使用第一个已启用模型，助手也可手动指定。旧单模型配置自动迁移，API Key 继续存系统钥匙串。

助手支持无选文提问、单词释义、翻译，以及“操作应用”模式：创建/重命名书架、整理书籍、修改主题/字体/朗读/导入上限、阅读导航和模型配置。删除书籍、删除书架/模型、清空回收站、移除标记、清除朗读历史会先显示具体确认；拒绝后停止本次操作。永久删除仅移除应用内副本，保留原始导入文件。清空回收站只处理确认时的书籍清单。

应用操作要求服务与模型支持 Chat Completions function tools。不会执行任意系统命令或让模型读取 API Key；操作范围和发送的数据见 [AI 说明](docs/AI-and-Neural-Voices.md)。0.5.0 的 55 项无界面测试通过，真实供应商与界面由用户验证。

### MCP 与语音聊天（0.6.0）

设置 → MCP 可启用本机服务并复制标准 stdio 客户端配置，让其他 AI 产品使用与应用内助手一致的操作工具；删除类仍需在 Readora 内确认。桥接程序随应用打包，不依赖额外运行时。

AI 助手 → 语音聊天：中文/英文识别、多轮问答、可选识别后自动发送、系统音色朗读与打断；仅主动录音时使用麦克风。详见 [连接与使用说明](docs/MCP-and-Voice.md)。0.6.0 的 63 项无界面测试通过，打包后原生桥接冒烟检查通过；按用户要求不进行界面或麦克风测试。

### 简化 AI 交流（2026-10-17）

AI 助手统一为文字/语音输入，自动判断阅读问答、解释、摘要、翻译或应用操作，无需切换任务模式。常规应用操作直接执行，删除等操作保留具体确认。模型与引用原文折叠展示，支持连续对话及快捷提问；发送时附带当前引用与最近对话，必要时通过工具查询应用状态。所有请求使用支持 Chat Completions tools 的已启用模型，意图判断质量取决于所选模型；真实服务尚需验证。

AI 面板仅显示当前回复，历史不再铺在界面中；连续追问的有限上下文仍在本次面板内保留，可用“清空对话”重置。输入区固定在底部，提供多行输入和⌘Return发送。
